SELECT custid, count(*) AS 구매한_도서수량 FROM orders
WHERE orderdate >= '2024-07-07'
GROUP BY custid HAVING count(*) >= 2;
# JOIN, ON

ON을 작성하지 않으면 모든 경우의 수가 다 나오는 카테시안 곱 형태로 테이블이 JOIN
FROM, JOIN 테이블 순서 - 기준이 되는 부모 테이블을 FROM에 먼저 적는 것이 관례

SELECT bookname, saleprice FROM book 
JOIN orders ON book.bookid = orders.bookid ORDER BY saleprice DESC;

SELECT bo.bookname, ord.saleprice FROM book AS bo
JOIN orders AS ord ON bo.bookid = ord.bookid ORDER BY saleprice DESC;
// 하지만 현업에서 코드는 혼자만 보는게 아니기 때문에 위와 같이 테이블에 별칭을 붙여줘서

# DB의 개념적 구조 : 각 단계 별로 다른 추상화 제공
외부 스키마(External Schema) : 개별 사용자 관점, 외부 스키마는 여러개 존재 가능, 서브 스키마라고도 함, 하나의 DB에 여러개 존재 가능
개념 스키마(Conceptual Schema) : 조직 전체 관점,  전체 DB에 어떤 데이터가 저장되는지, 어떤 관계가 존재하고 어떤 제약조건이 있는지에 대한 정의뿐만 아니라, 데이터에 대한 보안 정책이나 접근 권한에 대한 정의도 포함, 하나의 DB에 하나만 존재
내부 스키마(Internal Schema) : 저장 장치 관점, 전체 DB가 저장장치에 실제로 저장되는 방법 정의, 레코드 구조, 필드 크기 등 물리적 저장 구조 정의, 하나의 DB에 하나만 존재
스키마 사이의 대응 관계
외부/개념 매핑 : 외부 스키마, 개념 스키마의 관계, 응용 인터페이스(Application interface)
개념/내부 매핑 : 개념 스키마, 내부 스키마의 관계, 저장 인터페이스(Storage interface)
데이터 독립성 - 유지보수성을 위해 DB를 3단계로 나누고 스키마를 유지하며 대응관계 정의
* 데이터 독립성 : 하위 스키마를 변경하더라도 상위 스키마가 영향을 받지 않는 특성
논리적 데이터 독립성 : 개념 스키마 변경 -> 외부 스키마 영향 X, 개념 스키마 변경 시 외부/개념 매핑(응용 인터페이스)만 수정
물리적 데이터 독립성 : 내부 스키마 변경 -> 개념 스키마 영향 X, 내부 스키마 변경 시 개념/내부 매핑(저장 인터페이스)만 수정
데이터베이스 : 여러 사용자가 공유하여 사용할 수 있도록 통합해서 저장한 운영 데이터의 집합
데이터베이스 시스템 특징 - Real time Accessibility(실시간 접근성), Continuous Evolution(계속적인 변화), Concurrent Sharing(동시 공유), Content Reference(내용 참조)
SQL(Structured Query Language) : DBMS를 관리하기 위한 언어
DDL(Data Definition Language) 데이터 정의어: 스키마 생성, 변경, 제거 - CREATE 테이블 생성, ALTER 테이블 수정, DROP 테이블 삭제, TRUNCATE 테이블 초기화
DML(Data Manipulation Language) 데이터 조작어 : 데이터 삽입, 삭제, 수정, 검색 - SELECT 데이터 조회, INSERT 데이터 입력, UPDATE 데이터 수정, DELETE 데이터 삭제
DCL(Data Control Language) 데이터 제어어 : 내부적으로 필요한 규칙, 기법 정의(무결성, 보안, 회복, 동시성 제어) - GRANT 권한 부여 REVOKE 권한 삭제 COMMIT 트랜잭션 작업 완료 ROLLBACK 작업 취소 및 이전 상태로 복구
# 개체-관계 모델(ERD) : 개체와 개체간의 관계를 이용해 현실 세계를 개념적 구조로 표현
개체(Entity) : 사람이나 사물같이 구별되는 모든 것
속성 : 개체나 관계가 가지고 있는 고유한 특성, 키 속성 : 각 개체 인스턴스를 식별하는데 사용
관계 : 개체와 개체가 맺고 있는 의미 있는 연관성, 매핑을 의미, 1:1(일대일), 1:N(일대다), N:M(다대다)이 있음
# 관계 데이터 모델 : 개념적 구조를 논리적 구조로 표현하는 논리적 데이터 모델
● 릴레이션(relation) - 하나의 개체에 관한 데이터를 2차원 테이블의 구조로 저장한 것
- 파일 관리 시스템의 파일(file)
● 속성(attribute) - 릴레이션의 열
- 파일 관리 시스템 관점의 필드(field)
● 튜플(tuple) - 릴레이션의 행
- 파일 관리 시스템 관점의 레코드(record)
● 도메인(domain) - 하나의 속성이 가질 수 있는 모든 값의 집합 
- 속성 값을 입력 및 수정할 때 적합성 판단의 기준이 됨 
- 일반적으로 속성의 특성을 고려한 데이터 타입으로 정의
● 널(null) - 속성 값을 아직 모르거나 해당되는 값이 없음을 표현 
● 차수(degree) - 하나의 릴레이션에서 속성의 전체 개수 
● 카디널리티(cardinality) - 하나의 릴레이션에서 튜플의 전체 개수
// 릴레이션 스키마
- 릴레이션의 이름과 릴레이션에 포함된 모든 속성의 이름으로 정의
- 릴레이션 이름(속성 1, 속성 2, 속성 3, …) / 릴레이션 이름(속성 1: 도메인 1, 속성 2: 도메인 2, 속성 3: 도메인 3, …)
* 릴레이션 인스턴스 : 어느 한 시점에 릴레이션에 존재하는 튜플들의 집합
// 릴레이션 특징
❶ 속성은 단일 값을 가짐
❷ 속성은 서로 다른 이름을 가짐
❸ 한 속성의 값은 모두 같은 도메인 값을 가짐
❹ 릴레이션 내의 중복된 튜플은 허용하지 않음
❺ 속성의 순서는 상관없음
❻ 튜플의 순서는 상관없음
# 무결성 제약조건
● 데이터 무결성(Data Integrity) : DB에 저장된 데이터의 일관성과 정확성을 지키는 것
● 키 : 릴레이션에서 튜플들을 유일하게 구별하는 속성 또는 속성들의 집합
유일성, 최소성
기본키, 후보키, 대체키, 외래키, 슈퍼키
기본키 : 후보키 중 하나를 선정, 릴레이션 스키마 표현 시 기본키는 밑줄표시
기본키 고려사항 : 튜플을 식별할 수 있는 고유한 값, NULL값 X, 키값 변동 X, 최대한 적은 수의 속성, 향후 키 사용에 있어 문제발생 소지 X
외래키 : 다른 릴레이션의 기본키 참조
외래키 특징 : 외래키와 참조되는 기본키의 도메인이 동일, 참조되는 기본키 값 변경 -> 외래키 값변경, NULL값, 중복 값 허용, 동일 릴레이션의 기본키를 참조하는 외래키도 가능함, 외래키가 기본키의 일부가 될 수 있음
부모 릴레이션 : 참조 되는 기본키가 있는 릴레이션, 자식 릴레이션 : 외래키가 있는 릴레이션
● 도메인 무결성 제약조건 : 릴레이션의 튜플들이 각 속성의 도메인에 지정된 값만 가져야 한다.
● 개체 무결성 제약조건 : 기본키는 NULL값 X, 릴레이션 내에 오직 하나의 값만 존재
● 참조 무결성 제약조건 : 자식 릴레이션의 외래키는 부모 릴레이션의 기본 키와 도메인이 동일, 
자식 릴레이션의 값이 변경 될 때 부모 릴레이션의 제약을 받음
* 외래키 제약조건 옵션
CASCADE : 부모 테이블의 튜플이 변경될 때 자식 테이블의 튜플을 자동으로 변경
ON DELETE CASCADE : 부모 테이블의 튜플이 삭제될 때, 해당 튜플을 참조하는 자식 테이블의 모든 튜플도 삭제
ON UPDATE CASCADE : 부모 테이블의 기본키가 업데이트될 때, 해당 키를 참조하는 자식 테이블의 외래키 값도 함께 업데이트
SET NULL : 부모 테이블의 튜플이 변경될 때 자식 테이블의 외래키 값을 NULL로 설정
ON DELETE SET NULL : 부모 테이블의 튜플이 삭제될 때, 해당 레코드를 참조하는 자식 테이블의 외래키 값이 NULL로 설정
ON UPDATE SET NULL : 부모 테이블의 기본키가 업데이트될 때, 해당 키를 참조하는 자식 테이블의 외래키 값이 NULL로 설정
RESTRICT : 부모 테이블의 튜플이 변경될 때 자식 테이블의 튜플이 참조하고 있으면 변경 거부
ON DELETE RESTRICT : 부모 테이블의 튜플이 자식 테이블에서 참조되고 있으면 삭제 거부
ON UPDATE RESTRICT : 부모 테이블의 튜플이 자식 테이블에서 참조되고 있으면 업데이트 거부
NO ACTION : 부모 테이블의 튜플이 변경될 때 자식 테이블에 아무런 자동 변경도 수행하지 않음,

ON DELETE NO ACTION : 부모 테이블의 튜플이 삭제될 때 자식 테이블에서 참조되고 있으면 에러를 발생시키고 삭제를 수행하지 않음
ON UPDATE NO ACTION : 부모 테이블의 기본키가 업데이트될 때 자식 테이블에서 참조되고 있으면 에러를 발생시키고 업데이트를 수행하지 않음
